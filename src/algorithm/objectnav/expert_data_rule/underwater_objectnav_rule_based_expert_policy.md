# 水下 ObjectNav Rule-Based Expert 行为判断规则

## 1. 策略定位

该模块是一个完全硬编码的专家决策器。

目标检测或语义分割网络只负责识别图像中的 `echinus`、`rock` 和其他障碍，并输出类别、位置、置信度和深度等感知结果。Rule-Based Expert 读取这些结果以及 Global Map、Local Map，直接依据规则选择动作，不再经过任何动作预测网络。

输入与输出关系为：

**图像识别结果 + Depth + Pose + Semantic Map → Rule-Based Expert → Expert Action**

固定动作集：

| 动作 | 含义 |
|---|---|
| `FORWARD` | 向前移动一个固定动作原语 |
| `TURN_LEFT` | 原地向左旋转一个固定角度 |
| `TURN_RIGHT` | 原地向右旋转一个固定角度 |
| `STOP` | 已成功到达海胆目标 |

---

## 2. 决策所需信息

### 2.1 目标信息

- `target_visible`：当前是否检测到有效 echinus；
- `target_bearing`：目标相对相机中心的水平偏角；
- `target_distance`：目标与机器人的距离；
- `target_id`：当前锁定目标的标识。

方向约定：

| `target_bearing` | 目标位置 |
|---|---|
| 小于 0 | 目标在相机左侧 |
| 约等于 0 | 目标位于相机中心附近 |
| 大于 0 | 目标在相机右侧 |

### 2.2 环境信息

- 当前图像中左右两侧的 rock 数量或面积；
- Global Rock Channel：全局岩石分布；
- Global Explored Channel：已经观察过的区域；
- Global Visited Channel：机器人已经到达过的区域；
- Local Obstacle Channel：机器人附近的障碍分布；
- Local Obstacle Distance：机器人与附近障碍的距离。

此外，规则专家需要维护 `step_count`，表示当前 Episode 已经执行的离散动作步数；默认最大步数 `max_steps = 100`。

其中，Rock Channel 用于决定搜索方向，Obstacle Channel 用于决定能否安全移动。不能直接将所有 rock 都视为 obstacle；只有进入机器人碰撞包络的岩石才属于当前运动障碍。

---

## 3. 总体判断顺序

每次获得新观测后，严格按照以下顺序判断：

1. 若 echinus 可见且已到达成功距离，输出 `STOP`；
2. 若任务尚未完成且 `step_count >= max_steps`，将当前 Episode 判定为失败；
3. 若 echinus 可见，根据目标方向执行对准和接近；
4. 准备执行 `FORWARD` 时，检查前方障碍；若受阻，优先执行避障转向；
5. 若 echinus 不可见且需要重新观察，执行原地旋转；
6. 若 echinus 不可见且存在明显 Rock-rich Direction，朝该方向搜索；
7. 若 echinus 不可见且没有明显岩石线索，朝未探索区域搜索。

成功判断必须放在最大步数判断之前：如果第 100 步执行后已经满足成功条件，则任务成功；如果第 100 步后仍未满足成功条件，则任务失败。碰撞、越界、超步数或系统故障均由上层结束任务，不能输出 `STOP`。

---

## 4. 具体行为规则

### 4.1 启动观察

任务开始后，机器人先原地旋转观察周围环境，同时更新 Global Map。

将当前图像分成左、右两部分，并统计两侧的 rock 信息：

- 左侧 rock 数量明显更多：选择 `TURN_LEFT`；
- 右侧 rock 数量明显更多：选择 `TURN_RIGHT`；
- 左右数量接近、无法判断或画面为空：随机选择 `TURN_LEFT` 或 `TURN_RIGHT`。

如果使用目标检测，可根据 rock 检测框中心位于图像左侧还是右侧进行计数；如果使用分割，可比较左右两侧 rock 像素面积。

为了防止左右反复切换，一轮观察开始后应保持同一旋转方向，直到：

- 发现 echinus；或
- 达到设定的观察动作数或观察角度。

发现 echinus 后立即结束观察，进入目标接近规则。

### 4.2 多个 echinus 的选择

当多个 echinus 同时出现时：

1. 过滤置信度过低或深度无效的检测结果；
2. 根据目标区域内的有效深度计算目标距离；
3. 选择距离最近的 echinus；
4. 将其设为当前锁定目标。

目标距离优先使用分割区域内的深度中值；只有检测框时，使用检测框中心区域的深度中值，避免背景和岩石深度干扰。

目标锁定后不要每一步重新选择。只有当前目标连续丢失、深度持续无效，或者另一个目标明显更近时，才允许切换目标。

### 4.3 echinus 可见：对准目标

选定目标后，根据 `target_bearing` 直接选择动作：

| 判断条件 | 专家动作 |
|---|---|
| `target_bearing < -center_tolerance` | `TURN_LEFT` |
| `target_bearing > center_tolerance` | `TURN_RIGHT` |
| 位于中心容差范围内 | 准备执行 `FORWARD` |

`center_tolerance` 是相机中心附近的角度死区，用于防止检测框轻微抖动导致机器人左右振荡。

### 4.4 echinus 可见：接近目标

目标进入中心区域后：

1. 检查 `target_distance` 是否达到成功距离；
2. 若达到成功距离，输出 `STOP`；
3. 若尚未达到，检查 Local Map 中的正前方区域；
4. 前方安全时输出 `FORWARD`；
5. 前方受阻时不允许前进，进入避障规则。

接近过程不断重复：

**观察 → 对准 → 检查距离与障碍 → 前进 → 获取新观测**

如果目标短时丢失，优先朝目标最后一次出现的方向旋转。连续若干次仍未发现目标后，才返回原地观察或全局搜索。

### 4.5 前方受阻：避障

在 Local Map 中划分三个区域：

- 正前方通行走廊；
- 左前方区域；
- 右前方区域。

出现以下任一情况时，认为正前方不可通行：

- 正前方障碍占用比例超过阈值；
- 最近障碍距离小于安全距离；
- 岩石或其他障碍进入机器人的碰撞包络。

然后比较左右两侧净空：

- 左侧更空旷：`TURN_LEFT`；
- 右侧更空旷：`TURN_RIGHT`；
- 两侧接近：保持上一次避障方向；
- 没有历史方向：随机选择一个方向。

避障开始后应保持同一转向若干动作，避免出现连续的左右切换。转向后重新获取观测，再判断是否可以继续接近目标或恢复搜索。

### 4.6 echinus 不可见：选择 Rock-rich Direction

当当前视野中没有 echinus 时，利用 Global Rock Channel 选择搜索方向。

以机器人为中心，将 Global Map 划分为左侧、左前方、正前方、右前方和右侧等方向区域。每个方向综合判断：

- rock 的数量或密度；
- 该区域是否已经被反复访问；
- rock 周围是否存在可接近空间；
- 该方向是否存在明显障碍；
- 转向该方向需要的角度。

优先选择“岩石较多、访问较少、能够接近”的方向，而不是简单选择 rock 像素最多的方向。

只有当最佳方向的 rock 信息达到最低要求，并且明显多于其他方向时，才认为存在明确的 Rock-rich Direction。

选择方向后：

1. 保存当前搜索方向；
2. 根据方向偏差输出 `TURN_LEFT` 或 `TURN_RIGHT`；
3. 航向基本对齐后，检查前方障碍；
4. 前方安全时输出 `FORWARD`；
5. 连续移动一段距离或若干动作后，重新原地旋转观察；
6. 发现 echinus 后立即切换到目标接近规则。

同一段搜索过程中应保持当前搜索方向，不能每一步都根据微小地图变化重新选择。

### 4.7 无明显 rock 线索：探索未观察区域

当满足以下条件时进入无语义线索探索：

- `target_visible = false`；
- 各方向 rock 数量都很少，或不同方向差异不明显。

此时使用 Global Explored Channel 和 Visited Channel：

1. 选择未观察区域比例最大的方向；
2. 若多个方向接近，优先选择访问次数更少的方向；
3. 同时排除障碍风险明显过高的方向；
4. 仍无法区分时，保持上一搜索方向或随机选择方向。

选择方向后执行：

**转向 → 前进若干动作 → 原地观察 → 更新地图 → 重新判断**

---

## 5. 成功与失败判断

### 5.1 STOP 判断

`STOP` 只在以下条件同时满足时输出：

- 当前存在有效 echinus 检测；
- `target_visible = true`；
- `target_distance` 有效；
- `target_distance <= success_distance`。

为避免单帧深度噪声造成误停，可以要求成功条件连续满足若干次。

以下情况不能输出 `STOP`：

- 前方有障碍；
- 机器人被卡住；
- echinus 检测丢失；
- 目标深度无效；
- 碰撞、越界或超时；
- 当前没有明确搜索方向。

### 5.2 最大步数失败

每个 Episode 开始时令 `step_count = 0`。每执行一次 `FORWARD`、`TURN_LEFT` 或 `TURN_RIGHT`，`step_count` 增加 1。

默认设置：

- `max_steps = 100`；
- 第 100 步执行完成后重新获取观测；
- 若此时满足 STOP 条件，任务成功；
- 若仍不满足 STOP 条件，立即将 Episode 判定为失败；
- 失败终止不输出 `STOP`，也不允许继续生成第 101 个运动动作。

`STOP` 是任务完成信号，不计入上述搜索和运动步数。

---

## 6. 决策稳定性

规则专家需要保存少量行为状态，以保证动作连续性：

- 当前是否处于启动观察或周期观察；
- 当前观察方向和已观察角度；
- 当前锁定目标；
- 目标最后出现的方向；
- 当前选定的搜索方向；
- 已连续前进的动作数或距离；
- 上一次避障方向；
- 成功条件连续满足次数。

这些状态只用于规则判断，不需要交给任何动作预测网络。

当前机器人动作后约需 x（需要自己设定，目前先假设2） s 才能稳定，因此每次只输出一个动作：

**执行一个动作 → 等待稳定 → 获取新观测 → 更新地图 → 再执行下一次规则判断**

---

## 7. 关键阈值

| 参数 | 作用 |
|---|---|
| `detection_threshold` | 过滤低置信度 echinus 和 rock |
| `center_tolerance` | 判断目标是否位于相机中心 |
| `success_distance` | 判断是否到达海胆 |
| `target_lost_steps` | 判断锁定目标是否真正丢失 |
| `rock_direction_margin` | 判断某个方向的 rock 是否明显更多 |
| `safe_obstacle_distance` | 判断前方是否安全 |
| `observe_turn_steps` | 一轮原地观察的动作数 |
| `search_forward_steps` | 两次观察之间的前进动作数 |
| `avoid_turn_steps` | 避障时保持同一转向的动作数 |
| `max_steps` | Episode 最大运动与转向步数，默认 100 |

其中应优先实测：一次 `FORWARD` 的实际位移、一次转向的实际角度、机器人碰撞包络以及合理的 `success_distance`。

---

## 8. 完整行为逻辑

1. 启动后比较图像左右两侧的 rock，选择方向原地观察；
2. 若发现 echinus，选择最近且深度有效的目标；
3. 根据 `target_bearing` 左右转动，使目标进入相机中心；
4. 目标居中后检查成功距离，满足条件则 `STOP`；
5. 尚未到达时检查正前方通行性；
6. 前方安全则 `FORWARD`，受阻则向净空更大的一侧转向；
7. echinus 不可见时，根据 Global Rock Channel 选择 Rock-rich Direction；
8. 朝该方向移动一段后，再次原地观察；
9. 没有明显 rock 方向时，优先探索未观察且障碍较少的区域；
10. 每执行一次前进或转向动作，`step_count` 增加 1；
11. 若第 100 步后仍未满足成功条件，直接判定任务失败；
12. 重复上述判断，直到成功或上层结束任务。

整套专家行为由以上规则直接产生，不需要使用额外的策略网络进行动作选择。
